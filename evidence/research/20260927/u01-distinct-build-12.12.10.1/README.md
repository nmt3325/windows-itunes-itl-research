# U-01 distinct iTunes 12.12.10.1 build experiment

This directory retains a predeclared, exact-build experiment on the signed Apple standalone Windows x64 iTunes **12.12.10.1** executable (`0aa1b53a…31f9b`, 39,260,512 bytes). The selected build is non-adjacent to the retained 12.13.9.1/12.13.10.3/12.13.11.1 cohort. Public Apple installer provenance, Chocolatey package metadata, sizes, hashes, and Authenticode identities were locked and pushed before the first native launch. No Apple installer or executable is committed.

## Result

- **Positive:** iTunes 12.12.10.1 natively authored one deterministic WAV-backed library. The exact input (`154146cf…0cddc`) then passed two sequential open/snapshot/save/restart cycles. Cycle 2 consumed cycle 1's exact native save. Both cycles had two clean COM samples, all ten predeclared selected track values, the ordinary playlist and member order, separate outer/COM persistent-ID gates, independent parser confirmation, normal COM `Quit`, worker/iTunes exit 0, zero forbidden fallback artifacts, and zero remaining processes.
- **Predeclared negative:** the exact structurally valid 12.13.10.3 input (`c6c68171…92d74`) did **not** show the declared newer-version product modal in either fresh 90-second attempt. The harness therefore timed out and force-terminated iTunes twice. This is a failed negative, not a product-facing rejection and not a normally closed native qualification.
- **Timeout survivors:** after each completed failed-negative attempt, the surviving ITL had already changed hash and serialized version to 12.12.10.1 while preserving the selected reference track/playlist semantics under the independent parser. Those two files are retained because they disprove the unchanged-input/rejection gate, but force termination makes them observations rather than clean native cycles.
