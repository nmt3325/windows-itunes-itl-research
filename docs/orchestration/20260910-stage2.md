This is a development contract, not a claim of complete ITL semantics. The stage1 safety, native ownership, resource, privacy and preservation rules remain in force. ROOT, environment, worktree and lease come from the private parent runtime; no thread/control IDs belong in delivered code or evidence.

A row activates only when the parent assigns stage2 to that worker. Other workers continue their current task. ## Shared interface decision
Adopt the design in 20260910-api-contract.json with these constraints. Codec delivers schema/planning primitives as an early small commit before larger raw/coverage work, so dependencies can be integrated. Other engines build bounded pure helpers meanwhile; missing shared code is a dependency, not permission to create another owner's files or substitute unverified stubs as test evidence.

- ReadLimits fields are max_file_bytes, max_plain_bytes, max_nodes, max_depth, max_text_bytes, max_json_bytes, memory_budget_bytes. Initial new-engine defaults:16MiB file/plain, depth32,100000 nodes,4MiB text,64MiB JSON,512MiB declared process research budget. Pre-read/stat and decoded/model/JSON aggregate checks are separate. The process number is a measurement/limit target, not a guaranteed consequence of a decoded-size cap. Existing core512MiB behavior is not silently changed.
- FieldSpec/ProfileReport/ScopedID/ReferenceGraph are immutable or defensively copied records. Every interval/mask has an evidence level. A raw field never receives automatic semantic write authority.
- AllocationLedger is a frozen sequence of typed reservations: namespace, scope, old_identity, reserved_identity, consumers, capacity_check. Keep snapshot/file/master/track/FILE/album/artist/playlist/item identities, order tokens, string pools and cache ranks distinct. Graph/ledger data cannot be used as an unchecked caller-issued coverage certificate.
- PreparedMutation contains engine, intent, profile_report, baseline_digest, input_digests, allocation_ledger, typed_patches, opaque_preservation, postconditions, prepared_candidate_digest; it may privately hold immutable candidate bytes. Preparation isolates mutations and freezes all randomness/reservations. Apply verifies exact current inputs, candidate digest and all postconditions before one adoption. A deserialized report is never blindly executable authority. If an engine supports report replay, it must recompute admission and intent with the frozen reservation journal and reject tampering, extras, missing fields or stale pins. No new randomness during apply.
- Standard side-effect-free engine entry: prepare(target_bytes, intent, sources=None, *, limits=None, seed=None). Return a validated PreparedMutation or a structured blocked profile without publishing anything. Exact engine-specific intent keys must be documented and validated. Shared planning exposes apply(target_library, prepared) for atomic adoption; disk publication remains the existing exclusive write_new. Do not mutate a Library merely to calculate its input digest.
- Identity/graph modules expose bounded build_graph(data, *, limits=None), stable_graph(graph), and a reservation allocator. Freeze the exact small allocator signature in docs/identities-v2.md in the first commit and report it; other engines consume that pinned implementation after parent integration. Required operations distinguish local(kind), token(playlist_scope), persistent(kind, requested=None), atom(pool, source_binding, value), freeze(). Use deterministic seeded allocation or once-generated frozen reservations, bounded probes/capacities and conservative existing-byte exclusion. Dense pool IDs remain positive signed32 and default at most65535; local allocation defaults at most1000000 and4096 probes. Bounds are checked on both imported inputs and planned results. Retain retirement/reservation history within a transaction; do not guess a native high-water field.

## Feature priorities and evidence gates
1. Generic cross-library append from fresh independent native donor/recipient, with source-derived complete expectations. Admission is decoded profile/shape/invariants, not exact snapshot hashes/counts/PIDs or localized display names. The initial materializer may support a narrow positive structural/media profile; its restrictions must be explicit. Unresolved msph800/global/role/reference semantics block only where required proof is absent; obtain focused static evidence rather than deleting guards.
2. Scoped string and album/artist COW on the new shared corpus. Preserve every peer record, unrelated orphan, unknown byte and existing ordinary order. Allocate/repoint only selected closure. Default to retaining unresolved obsolete objects; no GC from PID-only scanning or zero known edges. Blank object identity and unknown compilation grouping remain separate.
3. Genuine newly generated media with format-derived constructor fields and consistent path13/URL11. Start with a proved PCM recipe and expand with one-factor native dimension controls; a template is a wire recipe, not permission to relabel arbitrary media. Type1-absent text-location profile can be developed separately; opaque type1 still blocks rebinding until decoded. No change to physical media during candidate acceptance.
4. Raw representation/coverage diagnostics are separate from semantic editing. Preserve library.v1. Initial explicit research raw schema allows same-sized opaque leaf replacements; header/shape/resizing permission requires a later explicit contract. Report this limit honestly.
5. Playlist models first expose ordered raw entries, parent-entry graph, ordered metadata occurrences and smart-rule wire trees with opaque leaves. Folder playlist parents are not mtph entry parents. No blanket smart evaluator or general grouped writer without native evidence.

Fresh native inputs are read-only under fixtures/dynamic4/snapshots; media manifest is reports/media/manifest.json, sealed initial-02. Their hashes are provenance, not admission constants. User-provided original files and derived private summaries are under private/** and remain parent-owned; do not copy into delivered evidence.

## Native scheduling
Dynamic remains the sole native owner. Existing synthetic discovery scope includes static requests N01 Location/path and N02 folder/smart controls, with N04 section diffs reused. Parent approves scheduling them after fresh corpus handoff without interrupting or repeating active native commands. Encoding/reference-only N03 awaits explicit constructed candidates and independent expectations. No system timezone/clock changes yet. No private-original native runs yet.

For each independent writer candidate, freeze intent/source/media expectations before construction; candidate-derived state alone proves only persistence. Require full old/new identities, metadata, Locations, visible and hidden playlist closure, normal saves/exits,45s then30s passive reopen, no repairing setters/UpdateInfoFromFile and no damaged/empty fallback. Playback is separate. Include allocator follow-up on a separate disposable copy. No generalized success claim from one fixture or one roundtrip.

## Reporting and commits
Use a new report phase, retain stage1 errors/inputs/logs. Commit only owned paths, with no executables/private originals/control metadata; parent reads the actual diff and independently checks results. Provide early reusable commits, complete command_id/exit/eof receipts and normal/adversarial/metamorphic tests. First implementation checkpoints should occur within30minutes of assignment, not only a final proposal. If communication with a running session fails, do not assume delivery or retry native work; use durable reports and wait for parent collection.
