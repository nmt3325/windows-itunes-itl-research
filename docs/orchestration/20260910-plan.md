# ITL continuation contract - 2026-09-10

## Baseline and objective
Baseline is private repository commit 82c10a7ada3e4ee829f222e22d0c2848d9179d79: 835 manifest entries verified; 976 core tests passed and 5 explicit COM-oracle skips reproduced on a new Windows runner. Prior native success is historical evidence, not a new-run result. Target is the Apple standalone Windows iTunes 12.13.10.3 binary pinned in the acquisition report; do not use Store/Apple Music instead. Complete semantic read/write is the objective, NOT the starting claim. Keep byte preservation, structural reconstruction, semantic mutation and native acceptance separate.

## Stage 1: independent surveys and native oracles
Explorers/reviewers may write only their own reports, scripts, prototypes and logs outside the source tree. They must not edit/commit production source. Submit a concrete first report within 25 minutes, then continue bounded experiments. Parent will approve a second-stage shared API contract before production extensions. Dynamic may add ONLY scripts/windows/continuation20260910/** in its own worktree. Media may add ONLY scripts/research/media20260910/** in its own worktree. Both may commit those owned additions, not existing files. Existing itlkit/**, tests/**, pyproject.toml, docs/format.md, CLI and shared contracts are parent-owned until reassigned explicitly.

## Runtime and ownership
ROOT, environment, deadline, absolute worktrees, Python and session mapping are in the parent-owned ROOT/runtime.json, outside git. Every exec has explicit assigned absolute cwd and pwsh; every command_id/next_byte is collected to exited/exit_code/eof. Idle/deadline is not completion. Only parent creates/destroys/extends environments or manages worktrees, dependencies, shared config, integration, push and PR. Do not reuse the destroyed previous runner or old job IDs. No grandchildren. Stop only your own processes. No exec_kill all. Read current tool schemas. Check base_sha before editing an existing file. Use explicit UTF-8; preserve old failure logs; inspect partial side effects before retrying.

## Resource limits
Each nonstatic role has at most one bounded lightweight command, normally <=512 MiB, and no unbounded loops. Static alone may run one headless decompiler with <=3 GiB heap. Queue workers are not a file mutex. Source, temp/cache/log directories and candidate names must be disjoint. No package installation except parent; static may acquire isolated verified decompiler tools under tools/static, media may acquire isolated verified encoder tools under tools/media. Do not redistribute third-party executables.

## Native exclusivity and evidence
Only dynamic launches/operates/quits iTunes, uses its COM/UI, or attaches live Frida. Other roles write native-requests.json to their own report directory and tell parent. Dynamic owns fixtures/dynamic4/**, reports/dynamic/** and experimental app preferences; media owns fixtures/media4/**, made immutable with hashes before native handoff. No Apple ID login, DRM bypass, cloud/device actions or original-media mutation. No clock/timezone change without an additional parent scheduling decision. Fresh metadata setters/AddFile controls are discovery oracles, not independent-writer acceptance.

Acceptance requests pin candidate/source/media hashes and include complete predeclared old/new identities, expected metadata and Locations, master/system memberships and ordinary ordering. Copy candidates to a new disposable live location; preserve inputs. No setters or UpdateInfoFromFile to repair a candidate during passive acceptance. Check immediately and after 45s on first open, then after a second 30s open; save/normal quit each time. Verify candidate->save1->save2 hashes, parsed reference closure, full COM enumeration and no damaged/empty fallback. Raw hidden playlists are checked independently; visible/raw count differences alone are not failure. Playback is a separate criterion. Discovery procedures may use shorter explicitly labelled controls, not masquerade as acceptance. Always report native ownership and clean restoration.

## Mutation proof obligations
Do not remove guards just to pass fixtures. Implemented general admission must be based on decoded version/profile/shape/invariants, not exact fixture SHA. During experiments hashes are required for provenance. Keep file/master/track/album/artist/item PIDs, local IDs, order tokens, pool-scoped IDs and sort caches distinct. No global ID replacement/zeroing, random huge dense-pool IDs, guessed unknown references or field resets. Preserve opaque state and reject unsupported semantic dependencies. Constructors must represent genuinely new media and identities; relabelled donor records alone are not proof of general construction. Preserve failure atomicity and existing-output refusal. Changes need normal, boundary, adversarial and metamorphic controls.

## Reports
ROOT/reports/<role>/report.json is owned by that role alone. Fields: task, role, status(in_progress/done/blocked/failed), phase, base_sha, head_sha, files_changed, checks[{name,command,command_id,state,exit_code,eof,log}], findings, native_requests, unsupported, contract_changes_needed. Keep append-only phase directories for successive experiments. Report first actionable results before completing the entire survey. Shared discoveries go through parent; do not edit another role's reports.

## Preservation and publication
Baseline source and evidence are frozen at ROOT/baseline and read-only. Shared Python is read-only; use -B, PYTHONDONTWRITEBYTECODE=1, PYTHONUTF8=1. Core check is PY -B -m pytest tests -q -rs -p no:cacheprovider with a unique report basetemp and ITLKIT_NATIVE_ROOT/REPORTS pointing at the frozen baseline fixtures/oracles. Tests never launch native applications unless dynamic explicitly invokes a native harness. Parent checkpoints validated source and sanitized synthetic evidence to the existing private GitHub repository. Never publish personal original ITLs/media/artwork, archive, credentials or internal control-plane/session metadata. Runtime and private inputs stay outside git. Development source intentionally adds files; do not call the historical delivery manifest a current development manifest. Do not rewrite baseline evidence or its historical manifests.

The runner has a shorter lifetime than the ten-hour watchdog. Parent will freeze/save work before expiry and issue an explicit replacement environment contract if needed. A completed session or test count alone is not proof of complete ITL support.
